## Retained ports

- **Non-ReBAR Vulkan allocation.** Probe the actual memory types and select the largest device-local heap as main VRAM. Preserve existing UMA, explicit host-memory and NVIDIA policy branches. The RX 580 exposes 7,936 MiB main VRAM and a separate host-visible 256 MiB BAR. Native reports `rebar: 0` after deployment. [PR 31658](https://github.com/ggml-org/llama.cpp/pull/31658) · [Reported regression](https://github.com/ggml-org/llama.cpp/issues/27097)
- **CPU Softmax.** Distribute independent rows across heads and batches only when the leading row count is smaller than the worker count. The row arithmetic and normal row assignment are preserved. A Haswell test with F16 masks and unmasked cases returned exact bytes in 20 comparisons. Speed is scoped to the operation. [PR 30923](https://github.com/ggml-org/llama.cpp/pull/30923) · [Operation evidence](../results/operations-2026-11-07.json)
- **Tensor allocation bounds.** Guard size rounding and compare capacity by subtraction. The original fail-fast contract and zero-size allocations are preserved. Test overflow, invalid alignment, exhausted capacity and valid allocations through the actual function with a bounded buffer fixture. [PR 26318](https://github.com/ggml-org/llama.cpp/pull/26318)

## Other decisions

- Device initialization already serializes publication and the buffer cache invalidates converted input after scratch reuse by FA or large Softmax. Descriptor reuse already uses a destruction generation check. The existing Vulkan shader includes the FA shared-memory write guard. [First-device race](https://github.com/ggml-org/llama.cpp/pull/29766) · [Scratch invalidation](https://github.com/ggml-org/llama.cpp/pull/29591) · [Descriptor reuse](https://github.com/ggml-org/llama.cpp/pull/29280) · [FA shared-memory bound](https://github.com/ggml-org/llama.cpp/pull/29988)
- The Q8_0 sign issue is relevant to Haswell when an external quantizer emits `-128`. The closed proposal clamps a legal raw value and changes the dot product. An exact exceptional path needs separate testing. The open wider Q8_0 MMVQ proposal was measured on RDNA3. Its local usefulness needs a Polaris-specific experiment given the different integer-dot path. [PR 31211](https://github.com/ggml-org/llama.cpp/pull/31211) · [PR 31196](https://github.com/ggml-org/llama.cpp/pull/31196)
- Q1_0 repack needs to be compared with the existing CPU route and quantization of activations before promotion. HIP GCN MMQ is a separate backend from the installed Vulkan path. Cooperative-matrix INT4 needs an advertised matrix capability. [Prism Q1_0](https://github.com/PrismML-Eng/llama.cpp/pull/233) · [HIP GCN MMQ](https://github.com/ggml-org/llama.cpp/pull/27841) · [SDCPP INT4](https://github.com/leejet/stable-diffusion.cpp/pull/2280)
- Current Vulkan RMSNorm already handles excess Y and Z workgroups. Long audio references in the separate audio fork exposed excess X rows and require a matching shader and dispatch change. This remains a candidate for the long-reference path, with additional parity tests needed for the fused KoboldCpp variants. [Upstream Y/Z fix](https://github.com/ggml-org/llama.cpp/pull/30145) · [Audio X fix](https://github.com/0xShug0/audio.cpp/pull/1120) · [RX 580 reproduction](https://github.com/0xShug0/audio.cpp/issues/1114)
