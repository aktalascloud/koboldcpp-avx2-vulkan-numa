## CPU

- Reordered the AVX2 `gemm4xN` loop to reduce spills, preserving the original F32 reduction order. The wide-format trial was slower on larger Q4_0, Q5_0 and IQ4_NL shapes, so the final port is restricted to Q8_0. [llama.cpp PR 31058](https://github.com/ggml-org/llama.cpp/pull/31058)
- The rollback port uses the existing index ordered by sequence position. It skips holes and unrelated sequences even when a parked slot reaches the end of the cache. The all-sequence path uses the occupied interval. The indexed implementation agreed with a full scan in 800 randomized mutations across two streams. [rdna-boosts PR 125](https://github.com/stew675/llama-cpp-rdna-boosts/pull/125) · [Issue 273](https://github.com/stew675/llama-cpp-rdna-boosts/issues/273)
- The current tree already has the AVX2 Q2_0 path and row-wise CPU padding. The low-IQ pragma targets Clang because GCC already unrolls the loops. Prism packed formats and the ExLlama packed weight layout use separate tensor representations. [llama.cpp PR 30447](https://github.com/ggml-org/llama.cpp/pull/30447) · [PR 30526](https://github.com/ggml-org/llama.cpp/pull/30526) · [PR 31420](https://github.com/ggml-org/llama.cpp/pull/31420) · [rdna-boosts PR 84](https://github.com/stew675/llama-cpp-rdna-boosts/pull/84) · [ExLlama PR 577](https://github.com/turboderp-org/exllamav3/pull/577)
- Retained the tested AVX2 branches for Q5_K, Q6_K, IQ3_XXS and IQ3_S. In the independent 3,000-case trial, the selected branches matched every original result. Q4_0 changed floating-point output and slowed down. The smallest Q4_K shape slowed down and larger gains were marginal. Both Q4 paths retain the original code. [llama.cpp PR 31061](https://github.com/ggml-org/llama.cpp/pull/31061)

## GPU and project discovery

- `infr` identified a real Polaris cost from emulated integer dot product. KoboldCpp already checks accelerated integer dot support. The local experiment reused GGML's scalar pipeline and tried a 128×64 tile for aligned Q4_K and Q6_K, gated by wave64, real GCN IDs, shader-core count and LDS budget. Four arms produced identical result bytes. Q4_K kept the wider tile, while Q6_K kept its previous geometry after the wide trial took longer. The other `infr` proposals concern first-submit splitting and MTP verify routing. [infr PR 12](https://github.com/KessokuNet/infr/pull/12) · [PR 11](https://github.com/KessokuNet/infr/pull/11) · [PR 16](https://github.com/KessokuNet/infr/pull/16) · [Issue 3](https://github.com/KessokuNet/infr/issues/3)
- The corrected RX580 LDS and proprietary driver gates are present in the local tree. The eGPU project targets Metal. The other Polaris runbook patch concerns TurboQuant and multiple cards. The `gfx803` container and compatibility repos target ROCm packaging, solver admission or Torch rather than the Windows Vulkan execution path. [LDS patch](https://github.com/doteyeso-ops/rx580-vulkan-fa-lds) · [Metal eGPU project](https://github.com/thiensubs/llama-cpp-rx580-egpu) · [Polaris multi-GPU](https://github.com/gaigher/Polaris-multi-GPU-llama) · [gfx803 ROCm](https://github.com/Schaka/rocm-gfx803) · [Compatibility graph](https://github.com/chboishabba/gfx803_compat_graph)
- RDNA cooperative-matrix attention, Intel Xe prefill and RDNA4 matvec use capabilities unavailable on this card. The K-quant transposed-A proposal uses a separate device weight layout restricted to cooperative-matrix pipelines. Its useful memory reuse principle was checked against the existing scalar LDS path and the wide-tile experiment. [PR 31323](https://github.com/ggml-org/llama.cpp/pull/31323) · [PR 29357](https://github.com/ggml-org/llama.cpp/pull/29357) · [PR 31804](https://github.com/ggml-org/llama.cpp/pull/31804) · [PR 22970](https://github.com/ggml-org/llama.cpp/pull/22970)

The larger-buffer audio proposal uses an optional 64-bit Vulkan indexing path. Current music uses the existing engine and allocator.
