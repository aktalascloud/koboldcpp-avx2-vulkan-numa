# Haswell and RX 580 upstream review · 2026-11-19

KoboldCpp `concedo_experimental` was at `ed246f4467157b3e5663feae28e7bf4d6990db39`, the base of the installed November 18 build. The two newer KoboldCpp PRs concern [text generation after a disconnect](https://github.com/LostRuins/koboldcpp/pull/2658) and [atomic save-data writes](https://github.com/LostRuins/koboldcpp/pull/2659). The [image detection and interleaved prompts PR](https://github.com/LostRuins/koboldcpp/pull/2648) was still open.

The review covered llama.cpp master (`e4b620af19`), GGML (`d9fe7bff3d`), stable-diffusion.cpp (`532d2c15c4`), Audio.cpp (`ced4b4b2a4`), ik_llama.cpp (`093e74cb0`), and the Polaris and Strata forks. These are the heads observed during the review.

| Path | Decision and evidence |
| --- | --- |
| Haswell CPU, Q8_K activation packing | Apply the AVX2/BMI1 maximum search. The [ARM proposal](https://github.com/ggml-org/llama.cpp/pull/32554) supplies the idea; the x86 change keeps the first tie and all original quantization math. The [operator test](haswell-q8k-20261119.json) matched 1,200 cases byte for byte. At width 4,096, median time went from 5.35 to 1.62 µs over 12 paired samples. |
| RX 580 image and attention kernels | Use the tested wave64 Vulkan path. The running RX 580 2048SP reports 32 KiB shared memory and no FP16 arithmetic, integer dot products or matrix cores. The reported CM1 changes target [WMMA accumulation](https://github.com/ggml-org/llama.cpp/pull/32528) and [aligned loads in WMMA kernels](https://github.com/ggml-org/llama.cpp/pull/32529); the [KV filter](https://github.com/ggml-org/llama.cpp/pull/32558) needs ray queries and cooperative matrices. The [November 18 profile](vulkan-rx580-20261118.json) locates the heaviest ABDM work in scalar Q8_0 and FlashAttention. On those matched shapes, the wide tile and single-operand LDS variants were slower. |
| Weight loading | The [mmap readahead PR](https://github.com/ggml-org/llama.cpp/pull/32515) changes Linux behavior. The Windows implementation already uses `PrefetchVirtualMemory`, and the tested photo profile uses a non-mmap path. |
| Audio engines | The [Audio.cpp MoE engine](https://github.com/0xShug0/audio.cpp/pull/1334) migrates Drama3, Ming3, Nemotron Transcribe and Zonos. Its CUDA results do not cover the current YuE2 path. The [HIP package trial](https://github.com/0xShug0/audio.cpp/pull/1316) needs matching ROCm kernels and its published package checks use gfx1151. |
| Video VAE | The [Hunyuan spatial padding PR](https://github.com/leejet/stable-diffusion.cpp/pull/2374) reports a large CUDA improvement and about 0.3% on its Vulkan test. The installed video path uses Wan and requires its own measurements. |
| Alternate GGML fork | The [ik_llama input-copy trial](https://github.com/ikawrakow/ik_llama.cpp/pull/2921) implements CUDA and CPU copies and depends on pinned memory for offload. The [dynamic context change](https://github.com/ikawrakow/ik_llama.cpp/pull/2931) removes that fork's fixed context table. This KoboldCpp tree already allocates contexts dynamically. |

The Q8_K result measures one CPU operation. Model speed also depends on which tensors reach that path, matrix multiplication, I/O, and GPU residency. The next RX 580 comparison should profile the existing scalar Q8_0 loads on the same ABDM shapes and check output bytes before testing request time.
